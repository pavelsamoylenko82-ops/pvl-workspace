# База знаний: боты и ИИ-агенты (разделы 17, 18, 19)

Структурированная выжимка по трём разделам: ИИ-агенты в соцсетях, свой ИИ-агент, Telegram-боты. Рабочие инструкции лежат в `skills/social-and-tg-bots.md` и `skills/ai-agent-architecture.md`. Сырых ключей, токенов и паролей в этом файле нет и быть не должно.

## 0. Границы и общие правила

- Секреты только в `.env`: токены ботов, API-ключи, app secret, ID чатов. В Git, документацию, логи и переписку попадают только имена переменных.
- Бизнес-математика (цены, количества, суммы, скидки, итоги, отчёты) всегда считается детерминированным кодом. LLM не принимает окончательных финансовых решений.
- Мутации данных и трата денег только после подтверждения человеком.
- Сомневаешься — остановись, сохрани состояние, передай человеку. Молчаливое вранье хуже отказа.
- Перед новым проектом брать каркас `Проекты/_Стартеры/03-tg-bot-aiogram`. Не менять структуру маршрутов и `.env`-переменные без задачи.

# Раздел 17. ИИ-агенты в соцсетях

## 17.1 Instagram Direct и комментарии: только официальный API Meta

### Подключение

- Профессиональный аккаунт Instagram + привязанная страница Facebook + приложение Meta for Developers.
- Давний подтверждённый аккаунт разработчика. Свежий непроверенный аккаунт чаще получает ограничения.
- Вебхук:
  - проверка `hub.verify_token` при подписке;
  - проверка подписи `X-Hub-Signature-256` по сырому телу запроса и app secret на каждом событии;
  - невалидная подпись — 403, событие не обрабатывается.
- Переменные окружения: `META_APP_SECRET`, `META_VERIFY_TOKEN`, `META_PAGE_ACCESS_TOKEN`, ID страницы/аккаунта. Значения не хардкодить.
- Окно ответа 24 часа с последнего сообщения пользователя. Первым не писать. Вне окна — только разрешённые политикой Meta шаблоны/теги или ждать нового входящего.
- Обрабатывать rate limit, ошибки API и повторы с backoff.

### Категорические запреты

- Логин/пароль от Instagram и автоматизация через браузер.
- Серые библиотеки, внутренние endpoints, обход официального API.
- Холодные массовые рассылки в Direct.
- Парсинг чужих чатов и контактов.
- Накрутка подписчиков, лайков, комментариев.
- Несколько аккаунтов для маскировки и обхода лимитов.

## 17.2 Голос и квалификация

- 1-2 предложения, один вопрос за раз.
- Без списков, markdown, длинных тире и канцелярита.
- Факты только из живых данных: каталог, прайс, наличие, расписание, карточка клиента.
- Не оценивать цену по фото. По фото уточнять модель/детали, цену называет человек или расчёт по прайсу.
- Нераспознанное голосовое — попросить текст. Если непонятно и в тексте — звать человека.
- Не выдумывать наличие, сроки, скидки, отзывы и кейсы.

## 17.3 Передача человеку: 7 триггеров

1. Жалоба или претензия.
2. Возврат, оплата или спор по деньгам.
3. Не хватает данных для корректного ответа.
4. Нестандартный заказ, опт, индивидуальный расчёт.
5. Просят живого человека.
6. Три сообщения по кругу без продвижения.
7. Заявка готова (запрос + контакты).

### Протокол

1. Клиенту одна фраза: «Передаю менеджеру, он подключится и уточнит детали».
2. Карточка менеджеру в Telegram: канал, ссылка на диалог, имя/username, суть, собранные данные, причина передачи, время.
3. Кнопки «Беру» / «Вернуть агенту». Только для менеджеров из allowlist по Telegram ID. `callback_data` короткая, обработка идемпотентная.
4. Агент молчит до возврата или 12 часов.
5. Если не взяли — повторный пинг через 15 минут, не чаще.
6. Через 12 часов — эскалация владельцу/старшему менеджеру.
7. Журнал: кто передал, кому, причина, время, кто взял, когда вернул, результат.

## 17.4 Демо-примерочная за 5 минут

- Парсинг главной страницы + максимум 2 внутренние страницы, 6-7 тысяч знаков суммарно.
- Два вида окна: чат на сайте и макет IG Direct.
- Лимит 10 сообщений на сессию, затем сообщение о лимите и кнопка связи с человеком.
- Суточный лимит по IP + общий предохранитель по запросам и стоимости API.
- CORS только для своего домена, без `*`.
- Защита от SSRF: только `http/https`, проверка DNS, запрет localhost, приватных IPv4/IPv6, link-local и metadata IP `169.254.169.254`, запрет редиректов на внутренние адреса. Таймауты и ограничение размера ответа.
- Кэш разбора 1 час.
- Отдельный демо-ключ API с урезанными лимитами и бюджетом. Боевой ключ не использовать.
- В демо только факты со страниц; спорное помечать «уточните у менеджера».

## 17.5 Комментарии: «слово → ссылка в Direct»

- Одно сообщение на ключевое слово одному пользователю. Повторно не отправлять.
- Регистронезависимое сравнение + допуск 1 опечатки (Левенштейн ≤ 1 для слов длиннее 4 символов).
- Только официальный private reply/Direct API, без массовых публичных ответов.
- При ответе пользователя в Direct — передать агенту по общим правилам.
- Журнал воронки: `comment_id`, `user_id`, слово, время, отправлено, ответил, передан человеку.
- Дедупликация по `comment_id` и `user_id`.

## 17.6 Чек-лист раздела 17

- [ ] Официальный API, подпись вебхука, окно 24 часа.
- [ ] Нет логинов/паролей, серых библиотек, холодных рассылок, накруток.
- [ ] Голос короткий, один вопрос, факты из живых данных.
- [ ] 7 триггеров и журнал передачи работают.
- [ ] Демо: лимиты, CORS, SSRF, кэш, отдельный ключ.
- [ ] Комментарии: одно сообщение, допуск опечатки, дедупликация, журнал.

# Раздел 18. Свой ИИ-агент: архитектура и точность

## 18.1 Разделение «Код / ИИ / Человек»

| Слой | Задачи | Запреты |
|---|---|---|
| Код | Правила, цены, количества, суммы, скидки, итоги, отчёты, статусы, права, валидация, даты, лимиты | Отдавать расчёты LLM |
| ИИ | Свободный текст, извлечение полей, классификация, черновики, смысловой поиск | Финальные финансовые и юридические решения |
| Человек | Подтверждение мутаций, оплат, отправок, исключений и спорных случаев | Массовое подтверждение вслепую |

- ИИ только на неструктурированный переменный вход.
- Любое число от LLM пересчитывается кодом и перезаписывается.
- Извлечённое поле хранится с источником и проходит валидацию диапазона.
- Трата денег и изменение данных — только после подтверждения человеком.

## 18.2 Четыре компонента до кода

### 1. Модель

- Провайдер, `base_url`, `model_name` — в одной настройке `.env`, без привязки логики к одному вендору.
- OpenAI-совместимый интерфейс/адаптер: смена модели = замена конфига.
- Модель `gemini-2.5-flash` запрещена.
- Таймауты, `max_tokens`, температура, лимит стоимости — в конфиге.
- Отдельный health-check модели.

### 2. Инструменты

- Чтение можно автоматизировать. Мутации и трата денег — только с подтверждением.
- Строгая схема аргументов, валидация, таймаут, понятная ошибка.
- Никакого универсального SQL/shell без allowlist.
- Идемпотентность мутаций и ключ операции.
- Лог вызовов без секретов.

### 3. Память

- Контекст и правила передаются в запрос явно.
- Уровни: правила проекта, карточка клиента, история заказа, контекст сессии.
- В промпт только релевантные фрагменты и источники.
- Секреты и лишние персональные данные не писать.
- При конфликте свежие данные из БД/кода выше старых заметок.

### 4. Цикл

- Жёсткие лимиты шагов и повторов в коде.
- Таймаут на цикл и каждый инструмент.
- При провале: стоп, статус «Разобрать вручную», алерт человеку.
- Предохранитель по стоимости.
- После 2 неудачных попыток — передача человеку, без бесконечных уточнений.

## 18.3 «Самоулучшение» через память правок

- Лог правок: было, стало, кто, когда, заказ/диалог, причина.
- В похожих случаях — подсказка из журнала, но не молчаливое применение.
- После 2+ однотипных правок — предложение перевести правку в правило.
- Новое правило включается только после подтверждения человека.
- Изменение правила можно отменить: версии и автор.
- Запрещено менять старые заказы и документы задним числом. Только новая версия/корректировка с датой и причиной.
- После нового правила — повторный экзамен.

## 18.4 Мультиагентность

- Старт с 1 стабильного агента.
- Второй агент — только при измеримой нехватке качества или разделения ролей.
- Maker-Checker:
  - Maker делает работу;
  - Checker получает только исходник и итог, без рассуждений Maker;
  - Checker не правит сам, а выдаёт список расхождений;
  - правку вносит Maker или человек, затем повторная проверка.
- Общая память:
  - новые записи сверху с датой и автором;
  - чужое не стирать, помечать устаревшее;
  - при конфликте верить коду и свежим данным.
- Считать стоимость, задержку и прирост качества. Мультиагентность не ради модности.

## 18.5 Экзамен и защита от тихого вранья

- Эталон 10-20 реальных кейсов, включая плохие сканы и неполные данные.
- Проверяет человек, не другая LLM. У каждого кейса эталонный ответ и источник.
- Минимум 5 ловушек: агент должен сказать «нет такого» / «не хватает данных», а не подменять слабым аналогом.
- У каждого числа — источник: поле БД, прайс, документ, расчёт кода.
- Сомнительное значение подсвечивать человеку.
- Дедупликация загрузки документов, чтобы не было двойных сумм.
- Контрольные цифры до/после релиза: заказы, суммы, средний чек, ошибки.
- После изменения промпта, модели, правил или инструментов — повторный экзамен. Без прогона релиз запрещён.

### Примеры ловушек

1. Товара/услуги нет в каталоге — «нет такого».
2. В документе нет суммы — «не хватает данных».
3. Плохой скан — запросить оригинал/человека.
4. Конфликт цены — показать оба источника и позвать человека.
5. Просят посчитать итог — считать кодом.
6. Просят изменить старый заказ задним числом — отказать, предложить корректировку.
7. Дубликат документа — распознать, не удваивать.

## 18.6 Чек-лист раздела 18

- [ ] Схема «Код / ИИ / Человек» зафиксирована.
- [ ] Модель и ключ в `.env`, вендор не зашит, `gemini-2.5-flash` не используется.
- [ ] Мутации и деньги только после подтверждения.
- [ ] Контекст передаётся явно.
- [ ] Лимиты шагов, повторов, времени, стоимости.
- [ ] Провал ведёт в «Разобрать вручную» + алерт.
- [ ] Журнал правок, правила после 2+ повторов, отмена.
- [ ] Maker-Checker и правила общей памяти.
- [ ] Экзамен 10-20 кейсов + 5 ловушек, проверен человеком.
- [ ] Контрольные цифры до/после релиза.

# Раздел 19. Telegram-боты на Python / Aiogram 3

## 19.1 Четыре типа ботов

| Тип | Назначение | Ключевой стандарт |
|---|---|---|
| Бот заявок | Принимает заявку и доставляет менеджеру/в группу клиента | Отдельный бот на клиента, `.env`, fallback, Europe/Minsk |
| Бот заказов | Ведёт заказ в рабочей группе по статусам | Одна карточка, лог нажатий, идемпотентность, роли по TG ID |
| Бот-воронка | Прогрев, анкета, оплата, канал, рефералка | UTM `?start=`, тихие часы, ручная оплата, одноразовая ссылка |
| ИИ-консультант / сервисный бот | Отвечает по базе знаний или шлёт служебные уведомления | Те же правила: `.env`, роли, логи, fallback, аудит |

## 19.2 Стандарт бота заявок

- Отдельный бот на каждого клиента.
- `BOT_TOKEN`, `MANAGER_CHAT_ID`, `CLIENT_GROUP_ID`, `TECH_CHAT_ID` только в `.env`.
- Доставка менеджеру или в группу клиента. Технические ошибки — Павлу, не клиенту.
- Кликабельные контакты: `tel:`, Telegram, при необходимости WhatsApp/Viber.
- Время `Europe/Minsk` через `zoneinfo`.
- Fallback при сбое Telegram: БД/файл/outbox + повтор. Потеря заявки недопустима.
- Чужим — «Это служебный бот», без раскрытия внутренних данных.
- Обработка `/start`, неизвестных команд и кнопок без падений.

## 19.3 Стандарт бота заказов в рабочей группе

- Карточка заказа создаётся один раз и обновляется.
- Лог: кто нажал, когда, какой статус.
- Кнопки идемпотентные, повторное нажатие не создаёт дубль. Все callback отвечают `answer()`.
- Напоминание, если заказ не приняли за 5 минут.
- Роли строго по Telegram ID.
- Отчёты строго по образцу клиента: колонки, порядок, единицы, итоги. Математика кодом.

## 19.4 Стандарт бота-воронки

- UTM/метки через `?start=`, сохранение источника и даты первого касания.
- Анкета кнопками, валидация ответов.
- Прогрев с тихими часами 23:00-10:00 по Минску. В тихие часы очередь, не отправка.
- Кнопка «Не присылать больше» работает всегда.
- Оплату подтверждает человек вручную.
- После подтверждения — одноразовая ссылка в канал с ограничением срока и отзывом после вступления.
- Рефералка: уникальный код/ссылка, учёт приглашённых, начисление только по подтверждённым правилам.
- Все статусы воронки логировать.

## 19.5 Обязательный 9-пунктовый аудит до сдачи

1. Запущена ровно одна копия бота, в логах нет `Conflict`.
2. Раздельные токены теста и прода в `.env`.
3. Все получатели нажали `/start`, бот им пишет.
4. Список ID клиента актуален, privacy mode в группах выключен.
5. Время `Europe/Minsk` проверено в заявке, логе, отчёте.
6. `callback_data` меньше 64 байт.
7. Сообщения больше 4096 знаков разбиваются без потери текста.
8. БД работает, сервис перезапущен и поднялся, данные сохранились.
9. Живое сообщение с телефона: заявка/кнопка/уведомление проверены на реальном устройстве.

## 19.6 Белые рассылки: жёсткое правило

- Только opt-in пользователям именно этого бота.
- Купленные базы, парсинг чатов и чужие контакты запрещены.
- Перед запуском — превью и подтверждение человеком.
- Паузы и лимиты в минуту/час/сутки, обработка flood wait.
- Тихие часы 23:00-10:00 по Минску.
- В каждом сообщении рабочая кнопка отписки.
- На холодный спам, массовый парсинг чатов и «прогрев» чужих контактов — отказ.

## 19.7 Чек-лист раздела 19

- [ ] Пройдены все 9 пунктов аудита.
- [ ] Токены и ID только в `.env`, тест и прод раздельно.
- [ ] Fallback сохранения заявок работает.
- [ ] Время Europe/Minsk.
- [ ] Кнопки идемпотентные, callback < 64 байт.
- [ ] Длинные сообщения разбиваются.
- [ ] Рассылки только opt-in, с отпиской и тихими часами.

# Синхронизация с прайсом SAMOLA Studio и правилами стека

## Прайс (актуальные пороги «от»)

| Услуга | Порог, USD | Порог, BYN | Что входит |
|---|---:|---:|---|
| Лендинг | от 200 $ | 600+ BYN | Одна страница, форма/заявка, адаптив |
| Сайт-каталог | от 350 $ | 1100+ BYN | Каталог без сложной корзины |
| Интернет-магазин | от 450 $ | 1450+ BYN | Корзина, заказ, уведомления, базовая админка |
| Telegram-бот | от 150 $ | 480+ BYN | Сценарий, меню, заявки, уведомления |
| ИИ-ассистент | от 250 $ | 800+ BYN | Ответы по базе, передача заявки менеджеру |
| Автоматизация | от 350 $ | за этап | Один процесс с понятным результатом |
| Абонентское сопровождение | — | 240-600 BYN/мес | Поддержка, правки, обновления |
| Только хостинг | — | 150 BYN/год | Без работ и доработок |

Правила:
- Ниже порога «от» не опускаться без пересмотра объёма.
- Скидка только через уменьшение объёма, не через снижение цены за тот же объём.
- Внешние расходы (домен, хостинг, платные API, фото, шрифты) считать отдельно и согласовывать до старта.
- В договоре сумма только твёрдой цифрой в BYN, без «от» и «примерно».
- Срок Telegram-бота и ИИ-ассистента: 3-5 рабочих дней после 50% предоплаты и материалов. Сроки не сокращать ради продажи.

- Внешние ИИ-функции: API DeepSeek или Gemini через OpenAI-совместимый адаптер.

# social-and-tg-bots — ИИ-агенты в соцсетях и коммерческие Telegram-боты

Применяется при разработке ИИ-агентов для Instagram Direct и комментариев, демо-примерочных, коммерческих Telegram-ботов заявок, заказов и воронок. Главный принцип: только официальные API, понятная передача человеку, безопасность секретов и проверяемая сдача.

## Блок 1. Instagram Direct и комментарии через официальный API Meta

### 1.1 Подключение и запреты

- Работать строго через официальный API Meta для профессионального аккаунта: бизнес-аккаунт Instagram, привязанная страница Facebook, приложение Meta for Developers.
- Вебхук принимать только после проверки подписи `X-Hub-Signature-256` (HMAC SHA-256 от сырого тела запроса с app secret) и `hub.verify_token`. Запрос без валидной подписи отклонять с 403.
- Секреты только в `.env`: `META_APP_SECRET`, `META_VERIFY_TOKEN`, `META_PAGE_ACCESS_TOKEN`, ID аккаунта/страницы. В коде, логах, документации и Git их быть не должно.
- Соблюдать окно 24 часа с последнего сообщения пользователя. Первым не писать. Вне окна отвечать только официальными шаблонами/тегами, разрешёнными политикой Meta, иначе ждать нового входящего сообщения.
- Запрещено: логин и пароль от Instagram, автоматизация через браузер, серые библиотеки и внутренние endpoints, массовые холодные рассылки, парсинг чужих чатов, накрутка подписчиков/лайков/комментариев, обход лимитов и несколько аккаунтов для маскировки.
- Использовать давний подтверждённый аккаунт разработчика Meta. Новый непроверенный аккаунт чаще ловит ограничения и блокировки приложения.
- Обрабатывать rate limit и ошибки API с backoff, не долбить повторно один и тот же запрос. Все входящие и исходящие события логировать без персональных секретов.

### 1.2 Голос и квалификация

- Отвечать в 1-2 предложениях, задавать один вопрос за раз.
- Без списков, markdown, канцелярита и длинных тире. Живой человеческий тон.
- Факты брать только из живых данных: каталог, цены, наличие, расписание, карточка клиента. Нет данных — честно сказать и передать человеку.
- Не оценивать цену по фото. По фото можно уточнить модель/детали, но итоговую цену называет человек или детерминированный расчёт по прайсу.
- Нераспознанное голосовое сообщение: попросить повторить текстом. Если и текстом непонятно — звать человека, не угадывать.
- Не обещать наличие, сроки, скидки и брони, которых нет в данных. Не выдумывать отзывы и кейсы.

### 1.3 Протокол передачи человеку (7 триггеров)

Передавать диалог менеджеру, если:
1. Жалоба или претензия.
2. Возврат, оплата или спор по деньгам.
3. Не хватает данных для корректного ответа.
4. Нестандартный заказ, опт, индивидуальный расчёт.
5. Пользователь просит живого человека.
6. Три сообщения по кругу без продвижения.
7. Заявка готова: есть запрос и контакты.

Порядок:
1. Клиенту одна короткая фраза: «Передаю менеджеру, он подключится и уточнит детали».
2. В Telegram менеджеру уходит карточка: канал, ссылка на диалог, имя/username, суть запроса, собранные данные, причина передачи, время.
3. В карточке две inline-кнопки: «Беру» и «Вернуть агенту». Обрабатывать только менеджеров из allowlist по Telegram ID, callback_data короткая и идемпотентная.
4. После передачи агент молчит до нажатия «Вернуть агенту» или до истечения 12 часов.
5. Если карточку не взяли, повторный пинг через 15 минут. Не спамить чаще.
6. Через 12 часов без реакции — эскалация владельцу/старшему менеджеру.
7. Вести журнал: кто передал, кому, причина, время, кто взял, когда вернул, результат. Без журнала передача не считается выполненной.

### 1.4 Демо-примерочная за 5 минут

- Парсить главную страницу и максимум 2 внутренние страницы, суммарно 6-7 тысяч знаков. Не обходить весь сайт.
- Два вида окна: чат на сайте и макет IG Direct. Один сценарий, разный визуальный контейнер.
- Лимит 10 сообщений на сессию. После лимита — понятное сообщение и кнопка связи с человеком.
- Суточный лимит по IP, глобальный предохранитель по количеству запросов и стоимости API. При превышении — временная блокировка и алерт.
- CORS только для своего домена, без `*`. Проверять Origin на сервере.
- Защита от SSRF: разрешать только `http/https`, резолвить домен и блокировать localhost, приватные диапазоны IPv4/IPv6, link-local, metadata IP `169.254.169.254`, редиректы на внутренние адреса. Ограничить таймауты и размер ответа.
- Кэш разбора сайта 1 час. Не парсить один и тот же URL на каждый вопрос.
- Отдельный демо-ключ API с урезанными лимитами и отдельным бюджетом. Боевой ключ в демо не использовать.
- В демо не выдумывать цены и наличие: только факты со страниц, спорное помечать «уточните у менеджера».

### 1.5 «Слово в комментариях → ссылка в Direct»

- Одно сообщение на ключевое слово одному пользователю. Повторно тому же пользователю не отправлять.
- Сравнение регистронезависимое, допускается 1 опечатка (расстояние Левенштейна не больше 1 для слова длиннее 4 символов).
- Отвечать только на официальный комментарий через разрешённый private reply/Direct API. Не писать публично «отправил в личку» массово.
- Если пользователь ответил в Direct — передать агенту по общим правилам, не продолжать бесконечно.
- Журнал воронки: comment_id, user_id, слово, время, отправлено ли сообщение, ответил ли пользователь, передано ли человеку. Дедупликация по comment_id и user_id.

## Блок 2. Telegram-боты на Python / Aiogram 3

### 2.1 Стандарт бота заявок

- Отдельный бот на каждого клиента. Не переиспользовать одного бота для разных компаний.
- Токен и ID чатов только в `.env`: `BOT_TOKEN`, `MANAGER_CHAT_ID`, `CLIENT_GROUP_ID`, `TECH_CHAT_ID`. Значения не хардкодить.
- Заявка доставляется менеджеру или в группу клиента. Технические ошибки — Павлу в технический чат, не клиенту.
- Контакты в заявке кликабельные: `tel:`, Telegram username, при необходимости WhatsApp/Viber.
- Время только `Europe/Minsk` через `zoneinfo`, с датой и временем в заявке и логах.
- Fallback при сбое Telegram: сохранить заявку в БД/файл/outbox и повторить отправку. Потеря заявки недопустима.
- Чужим людям бот отвечает «Это служебный бот» и не раскрывает внутренние чаты и данные.
- Обрабатывать `/start`, неизвестные команды и кнопки без падений. Логировать ошибки.

### 2.2 Стандарт бота заказов в рабочей группе

- Карточка заказа создаётся один раз и дальше обновляется, а не дублируется новыми сообщениями.
- В карточке лог статусов: кто нажал, когда, какой статус. Telegram ID и имя.
- Кнопки идемпотентные: повторное нажатие не создаёт второй заказ и не ломает статус. Все callback отвечают `answer()`.
- Если заказ не приняли за 5 минут — напоминание ответственному.
- Роли строго по Telegram ID: менеджер, исполнитель, администратор. Чужие кнопки игнорировать.
- Отчёты формировать строго по образцу клиента: те же колонки, порядок, единицы и итоги. Математика и итоги — кодом, не LLM.

### 2.3 Стандарт бота-воронки

- UTM/метки через `?start=...`: сохранять payload, источник и дату первого касания.
- Анкета кнопками, а не свободным текстом там, где можно выбрать. Валидировать ответы.
- Прогрев с тихими часами 23:00-10:00 по Минску. В тихие часы сообщения не отправлять, ставить в очередь.
- Кнопка «Не присылать больше» работает всегда: один клик, запись в БД, исключение из всех рассылок.
- Ручное подтверждение оплаты человеком. После подтверждения — одноразовая ссылка-приглашение в канал, с ограничением срока и отзывом после вступления.
- Рефералка: уникальная ссылка/код, учёт приглашённых, начисление только по подтверждённым правилам. Не начислять за саморегистрацию.
- Все переходы и статусы воронки логировать.

### 2.4 Обязательный 9-пунктовый аудит бота до сдачи

1. Запущена ровно одна копия бота, нет `Conflict` в логах.
2. Раздельные токены теста и прода в `.env`, боевой токен не используется локально.
3. Все получатели нажали `/start`, бот реально может им писать.
4. Список ID клиента актуален, privacy mode в группах выключен, бот видит сообщения.
5. Время `Europe/Minsk` проверено в заявке, логе и отчёте.
6. `callback_data` меньше 64 байт, статусы и кнопки не ломаются.
7. Длинные сообщения больше 4096 знаков разбиваются на части без потери текста.
8. БД работает, сервис перезапущен и поднялся, после ребута данные и статусы сохранились.
9. Живое сообщение отправлено с телефона, заявка/кнопка/уведомление проверены на реальном устройстве.

### 2.5 Жёсткое правило белых рассылок

- Только пользователям, которые дали opt-in именно этому боту. Купленные базы, парсинг чатов и чужие контакты запрещены.
- Перед запуском — превью и подтверждение человеком.
- Паузы и лимиты по количеству сообщений в минуту/час/сутки, обработка flood wait.
- Тихие часы 23:00-10:00 по Минску. В это время очередь стоит.
- В каждом сообщении рабочая кнопка отписки.
- На запросы холодного спама, массового парсинга чатов и «прогрева» чужих контактов отвечать отказом.

- [ ] Официальный API, подпись вебхука, окно 24 часа.
- [ ] Нет логинов/паролей, серых библиотек, холодных рассылок и накруток.
- [ ] Голос 1-2 предложения, один вопрос, живые данные.
- [ ] 7 триггеров передачи и журнал работают.
- [ ] Демо: лимиты, CORS, SSRF, кэш, отдельный ключ.
- [ ] Комментарии: одно сообщение, дедупликация, журнал.
- [ ] Пройден 9-пунктовый аудит бота.
- [ ] Рассылки только opt-in, с отпиской и тихими часами.

# Правила работы (DeepSeek CLI)

## Обо мне
Павел, Беларусь. Делаю бизнесу сайты с онлайн-записью, ИИ-консультантов, Telegram-ботов и автоматизацию на Python. Работаю в соло.
Отвечай по-русски, коротко, по делу. Сначала решение или результат, потом детали.

## Стек и архитектура
- Бэкенд и боты: Python 3.11+, FastAPI, Aiogram 3, Playwright, PostgreSQL/SQLite.
- Сайты и лендинги: чистый HTML/CSS/JS или лёгкий стек под быстрый деплой (Vercel / VPS).
- Внешние ИИ-функции для клиентов: API DeepSeek или Gemini (название модели и API-ключ всегда выносить в .env, никогда не хардкодить).

## Память и структура проекта
- Важные решения, договорённости и изменения фиксируй в файлах сразу, не жди конца сессии.
- Папка клиента: Клиенты/<клиент>/ПАМЯТЬ.md (задача, решения с датой, что сломалось и как починили, что нельзя трогать). Новые записи сверху.
- Карточка лида/клиента: Карточки/<имя>.md (статус, деньги получено/ждём, обещания, следующий шаг с конкретной датой).
- ПУЛЬТ.md: сводка на сегодня, неделю, ожидаемые оплаты и молчуны. Обновляй при любом изменении карточек. На запрос «что по делам» отвечай по пульту, начиная с денег.
- Пароли, токены и ключи строго в ДОСТУПЫ.md и .env. Никогда в ПАМЯТЬ.md, код или лог чата.

## Перед изменениями
- Перед крупным рефакторингом создавай резервную копию файла/модуля для отката.
- Меняй только то, о чём я попросил. Перед правкой укажи список файлов, которые затронешь.
- Удаление файлов и платные запросы к API только после моего подтверждения.

## Сайты и лендинги
- Код пишем только после согласованного плана дизайна (5 hex-цветов, 2 шрифта с кириллицей, композиция, фирменный приём).
- Запрещено: шаблонные бежевые фоны с жирным чёрным заголовком, три карточки с иконками как основа сетки, градиентный текст, эмодзи вместо SVG-иконок, стоковые люди, шрифты Inter, Roboto, Arial, длинные тире.
- Mobile-first вёрстка, проверка под 360px и 1440px.
- Никаких выдуманных цен, отзывов и цифр. Если данных нет, скрываем блок или пишем «уточняйте по телефону».
- Перед сдачей: проверить отсутствие слов «демо», «тест», «lorem», «TODO» в видимой части, проверить реальную отправку формы в Telegram.

## Маршрутизация сайтов
При создании или редизайне любого сайта или демо сначала читать `skills/design-unslop.md` и `skills/commercial-site-gate.md`.
Перед сдачей запускать `python tools/seo_check.py` и прикладывать отчёт.
Без этих шагов работа не начинается и сайт не сдаётся.

## Тексты клиентам
- Перед генерацией сообщения читай СТИЛЬ.md.
- Пиши живо, без канцелярита, шаблонов ИИ («индивидуальный подход», «широкий спектр услуг») и длинных тире.
- КП расписывай по пунктам с вилкой цен в заголовке и выгодой для бизнеса.
- Напоминания об оплате всегда с конкретным днём («Проведёте сегодня?»).

## Документы
- Договоры, акты и счета сохраняй в Документы/ в формате <клиент>, <документ>, <сумма>.docx.
- Договор на 1-2 страницы, этапы таблицей, расчёты в BYN (для РБ) или RUB (для РФ), работа только после предоплаты.

## Стандарты генерации кода (Zero Stubs)
- Выдавай только полный, готовый к запуску код от импортов до финальной строки.
- Категорически запрещены заглушки: `// TODO`, `// остальной код реализуйте сами`, `pass` вместо логики или сокращения ради экономии места.
- Разделяй бизнес-логику, работу с БД/API и слой ввода-вывода. Все секреты и модели только через `.env`.

## Использование шаблонов (_Стартеры)
- Никогда не начинай типовой проект с пустой папки.
- Перед созданием нового проекта скопируй подходящий каркас из `D:\учеба\PVL\Проекты\_Стартеры`:
  - `01-landing-tg` для сайтов и демо-лендингов;
  - `02-ai-consultant` для ИИ-виджетов на сайт;
  - `03-tg-bot-aiogram` для Telegram-ботов.
- Не меняй рабочую структуру маршрутов и `.env`-переменных без явной задачи.
## Система карточек и Пульт
- На каждого клиента и лида ведётся файл `Карточки/<Имя (компания)>.md`.
- При упоминании человека в диалоге сначала прочитай его карточку. После изменений обнови карточку (новые записи сверху с датой ГГГГ-ММ-ДД) и запусти `python собрать.py` для обновления `ПУЛЬТ.md`.
- Руками `ПУЛЬТ.md` не править. Справочник 20 скиллов лежит в `Скиллы/INDEX.md`.

## Автопилот и границы доступа
- **Делаешь сам без спроса:** вёрстка, тесты, скриншоты через эмуляцию мобильного экрана (360/390/1440px), выкладка на тестовый preview-адрес, обновление карточек и памяти.
- **Только после моего «да»:** выкладка на боевой домен, правки DNS/сервера, удаление файлов (сначала резервная копия), платные запросы к API (сначала назови цену), отправка любых текстов клиентам.
- **Никогда не делаешь сам:** ввод паролей, кодов из SMS, регистрация аккаунтов, оплата сервисов. Если ключ попал в чат или Git - сразу предупреди о необходимости пересоздать его.
- **Экономия контекста и правило 3 кругов:** не читай весь проект ради правки одной кнопки. Если правка ломает соседний код 3 раза подряд - остановись, откатись и переспроси задачу.
